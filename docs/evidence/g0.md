## Current resource evidence

The final 21-test run recorded **45,064 B post-stop application heap** and
**63,576 B peak while old and incoming bitmaps overlapped**. After the measurement,
logging allocated 112 B. Four bitmap replacements per session cycle through
195/256/390 px with the 16-color palette; there are 40 sessions. The trace never
exceeds 180 points. Stop clears image, trace, coordinates, timer, subscription and
network job. The first session feeds 7,200 one-second event timestamps rapidly;
it is not two hours of elapsed runtime. These figures cannot establish the
physical graphics heap, long-term battery use or NFR acceptance.

Offline GUI diagnostics showed Phone NO, Images 0, GPS 204 and Trace 83 with live
coordinate age 0 seconds; the native saved screenshot was taken shortly afterward.
API and HTTPS tunnel were not running. All GPS input was an explicitly loaded
synthetic Utrecht GPX, not a physical/user position. English remained active while
the simulator's system language was Turkish. The session ended on the home screen.

Earlier direct-render Utrecht PNG samples: 195 day/night 8,429/8,410 B; 256 day/night
11,566/11,541 B; 390 day/night 21,770/21,790 B. Fixed Amsterdam and Brussels
390 px samples were 29,274 and 35,273 B. Individual local renders took approximately
0.84–2.12 seconds; these are samples, not p95 or Garmin transfer latency. The
provider's free service has no SLA. Dense tiles above 1 MiB are rejected explicitly.

Watch RAM limits: 180 trace points; one active plus one incoming image; one map job;
96 KiB free-heap reserve before requesting. No persisted GPS history or map cache.
Server limits: 9 viewport tiles, 1 MiB each, 16 entries AND 8 MiB compressed cache,
one decoded tile at a time, one render at a time, 18-second deadline, 64 KiB output,
24 output entries. These are separate server budgets, not watch storage.

The final real HTTP smoke test used a fixed Utrecht z15 view: six profiles PASS,
10,756–32,856 B, 1.32–1.97 seconds per metadata+PNG job. Unauthenticated render
was rejected with 401, palette used at most 16 colors and the API was stopped.
See [HTTP record](openfreemap/http-smoke.json); it is not the Garmin bridge.

## Historical checks and failures

The earlier synthetic-grid experiment (18:49:58–19:12:03 UTC) displayed all six
raster profiles via temporary HTTPS/Garmin conversion. During an API outage GPS
advanced 360→485, raster stayed intact and trace remained 180; automatic recovery
advanced Images 12→13. A 1024-character Storage round trip passed. Earlier large
Storage experimentation failed with OOM; capacity remains unknown. The tunnel was
closed and private configuration restored. See [historical record](previous-synthetic-simulator.json).
Those tiny grid PNGs and older Turkish screenshots are not current real-map evidence.

Corrections in the new extension: compressed cache eviction byte accounting;
separate render/image locks; explicit provider failure without synthetic fallback;
palette RGB channel conversion; English labels shortened after round-width failures;
GPS coordinates accepted outside Mercator coverage. All corresponding regressions pass.

PNG conversion findings remain documented in [ADR 003](../decisions/003-simulator-findings.md).
